## 四 · 实际运行验证出来的结论（区别于"读文档得出的"）

1. **三条版本硬约束是撞出来的**：PySide6 必须 6.8.x（6.12 import 即 WinError 127）；
   onnxruntime 必须 ≤1.20.x（1.21+ `WinError 1114`，逐版本二分到 1.20.1/1.21.0 边界）；
   **两个 ORT 发行版共存 = `import` 段错误 exit 139**，不抛异常，所以必须有 G21 守卫。
2. **"GTX 1060 支持 CUDA ⇒ 后端兼容"被证伪**：本机 providers 只有 `Dml/CPU`。
3. **"量化一定更快"被证伪**：int8 在 DirectML 上比 fp32 慢 1.85×。
4. **全量 OCR 不可行**：这是本阶段最重要的负面结论。1,144 GPU 小时（143 个工作日），
   比无人值守预算慢 11.6 倍。p5 保持 RED，没调阈值粉饰。
5. **文件监听不能作为唯一变更来源**：被监听根被改名时 0 事件；停机期间的变更只有扫描能发现。
6. **路径身份必须 `realpath`**：8.3 短名会把空格吃掉，纯字符串规范化归一不了。
7. **FTS5 三处静默陷阱**：`unicode61` 中文 0 命中不报错；`<3` 字 trigram 查不中要 LIKE 回退；
   `'delete'` 少带一列留幽灵行且**不报错**。
8. **实际量级 ≠ SPEC**：7,768 份（SPEC 写约 5,000）、202 万页、37.5% 纯扫描件。
9. **新算出来的硬约束**：全文索引外推 **28–48GB**（×10 档 280–480GB 不可行）—— 这条改产品形态，需要你选。
