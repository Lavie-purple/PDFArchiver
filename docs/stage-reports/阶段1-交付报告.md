## 四 · 真跑出来的结论（不是读文档读出来的）

1. **`QWidget` 必须在 `QApplication` 存在之后构造**，否则进程**直接 abort（exit 127，没有任何 traceback）**。
   测试夹具因此统一依赖 `qapp`。已登记为 V14。
2. **sqlite3 的隐式事务让 DDL 的提交时机不可控** —— 你以为在事务里，其实已经落地。
   所以 `isolation_level = None` + 手写 `BEGIN IMMEDIATE` 是迁移能"失败回到原样"的前提，不是风格问题。（D-023）
3. **`INSERT … ON CONFLICT(path_key) DO UPDATE` 的 SET 列表里多一个字段就是一次数据破坏**：
   把 `parse_status` 也刷上，重扫会把索引状态和人工确认位冲掉。注入 I8 就是专门证明这条断言会红。
4. **"格式合法"不等于"口径正确"**：I16 注入的是裸本地时间却标 `Z` —— 时间戳完全合规模、时刻差 8 小时。
   只有"同一次启动跨日志比时刻"这种断言能抓。这就是 D-022 的由来，也是本项目最贵的一条教训。
5. **本机控制台是 GBK**：`subprocess` 不显式 `encoding="utf-8"` 时，中文报错让解码线程炸掉，
   `proc.stdout` 变成 `None`，报错现场直接消失（阶段 0 踩过，本阶段又踩在产品侧测试里）。已写成约定。
6. **判空表当"是否首启"是错的**：用户把默认模板删光后重启，树会自己长回来 —— 语义上就是应用擅自改用户数据。
   改成 `app_settings['catalog.default_seeded']` 标记（D-020）。
7. **反向注入比测试本身更有信息量**：18 条坏法里 I11/I12/I13 三条是"断言写在了根本不会执行到的位置"这一类，
   不注入就永远不知道它一直在绿。
8. **13 张表里没有 `text_pages / content_fts / duplicate_groups`**，这是决定不是遗漏：
   Q1（分词）与 Q2（索引范围）未答，现在建了阶段 2 必返工；有断言反过来证明它们不存在。
