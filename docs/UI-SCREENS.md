阶段 1 交付的 UI 是**不含任何布局决策的运行时外壳**（决定过程与代价写在 **D-018**）：

## 三 · 无论选哪个方案，都已经由实测决定的界面约束

这些不是审美选择，是阶段 0 数字逼出来的，线框阶段就得遵守：

| 约束 | 来源 | 界面后果 |
| --- | --- | --- |
| 列表**必须虚拟化**，禁止一次渲染全部 | p0/p2：7,768 份、单目录最多 722 份、×10 档 8 万份 | 库视图与搜索结果都用 `QTableView` + 模型按需取行；不许 `QListWidget.addItem` 循环灌全量 |
| 打开文档**不能阻塞 UI** | p2：最大 946 页 / 1.1GB 单文件；`open_ms` 最差 232.7ms | 首屏先出文件名与元数据，正文页按需渲染（p3：单页 135.1ms 中位） |
| 搜索框需要**分档提示** | p1：<3 字 trigram 命中不了，需 LIKE 回退（2 字 499ms、单字 424ms） | 短查询要显示"正在用慢速匹配"并限制结果数，否则 500ms 门禁会被无感触发 |
| OCR / 语义是**可关闭的进度**，不是默认步骤 | p5：全量 101 万页按 6,000 页/日 = **169 天**；阶段 5 实测单页 1,985–5,780ms、一轮 6 页吃 **1,332MiB 显存**；p6：全量 7.6h；G9 GPU 只能串行 | 必须有一条统一的"后台任务队列"状态区，并显示当前占用 GPU 的是哪个任务；OCR 还必须显示**今日页预算已用/剩余**与**跑满即停**这件事（现在界面上完全看不见 → I23） |
| 索引体积要**当数据显示出来** | docs/RISKS 2.9：索引 28–48GB | 设置里显示索引体积与磁盘剩余；按 2.9 选 2（子集索引）时更是核心指标 |
| 归档确认屏必须显示"跨盘" | SPEC 3.6 + docs/DATABASE 状态机（跨盘必须先复制校验再删源） | A4/B3 里每条计划行要能看出 同盘 rename / 跨盘 copy+verify+delete |
| 危险操作不得只靠一次点击 | SPEC 4.3 | A4/A8 用"输入确认词"或"复选框 + 显示影响条数"，不许 `QMessageBox.question` 一下就完 |
| 窗口最小宽度基线 | p3：离屏 1280×800 布局通过 | 线框按 1280×800 与 1440×900 两档画；最小宽度数值由你定，我不替你猜 |

## 五 · 阶段 5 做完 OCR 之后新冒出来的读数需求（**未画线框，一屏都没写**）

AGENTS.md 的规矩是"每新冒一个界面 = 回环节 2 重过"。OCR 这一层落地的能力目前**只在服务层**
（`services/ocr_service.py`，用法见 `docs/OCR.md`），下面三件事必须同屏可读，否则用户拿到的是一个
"看起来什么都没发生"的 OCR。**它们并到哪一屏由你决定，我不自己加屏。**

| # | 必须可见的事 | 为什么必须有（实测证据） | 现成的落点候选 |
| --- | --- | --- | --- |
| O1 | **点名回执**：点名 N 份、实际排进队列 M 份、另 N−M 份**为什么没进**（已当前 / 不需要 / 预算已满 / 还没索引） | 门禁打印的是「点名 1 份｜该跑 1 份｜新增任务 1 条」这种分组回执；服务层已经算好了，**界面上一个地方都没有** | A7 或 B5 的一个标签页；也可做 A1 批量操作后的浮层 |
| O2 | **今日页预算 已用 / 上限 / 剩余**，以及"跑满即停"这件事本身 | D-028 用它替换了 G13；跑满停机时任务终态是 `cancelled` 且原因写在 `last_error` —— 不显示就等于"队列无故少了一批" | A7 / B5 常驻一行；状态页（已批准那一屏）能立刻加，因为它是文本行不是布局 |
| O3 | **单页耗时/失败与重试**：哪一页识别失败、原因、`attempts`、是否被单页超时判停 | `test_失败页不写行下次只补它`：失败页不留版本记录 ⇒ 一定会回到待办；用户若看不见就会反复重跑整本 | A2/A7；与阶段 2 已有的"任务错误/重试"读数是同一套口径 |

**另有两条与线框无关、但画屏之前必须知道的**：
- 搜索结果里 **OCR 命中必须和原生命中长得不一样**（库里 `source_kind` 已经分开，实测标签是
  「OCR 识别（可能有错字）」）。把识别文本渲染成"原文"是 SPEC 五·不许凭空编造的正面违规。
- **不许出现"OCR 进度百分比 = 整库还剩多少"的读数**。按需点名 + 169 天全量这两个事实放在一起，
  任何"总进度"都会是假数字；能显示的只有"本次点名的这 N 份里第几页"（`done/total`，实测 `2/4`）。
