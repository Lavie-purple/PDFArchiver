## 一 · 两个候选方案

### 方案 A · 8 屏（功能与 SPEC 3.1–3.8 一一对应）

| # | 界面 | 覆盖 SPEC | 为什么需要独立一屏 |
| --- | --- | --- | --- |
| A1 | 主窗口 · 库视图（虚拟列表 + 侧栏导航） | 3.2 / 3.3 | 文档浏览、分类树、标签、智能集合的唯一常驻入口 |
| A2 | 搜索结果面板（可嵌入 A1 右侧，也可独立） | 3.4 | 全文 / OCR / 语义三套结果要能同屏对比、标注命中来源 |
| A3 | PDF 阅读器（独立窗口） | 3.5 | 长时间阅读，需要自己的缩放/翻页/文本选取/高亮跳转 |
| A4 | 归档预览与确认（模态） | 3.6 | **唯一会动用户磁盘的界面**，必须强制"先看计划再确认" |
| A5 | 操作日志与撤销（独立视图） | 3.6 / 4.3 | 崩溃恢复与 undo 的可见入口，出事时要能一眼看完 |
| A6 | 重复文件检测（分组视图） | 3.7 | 结果形态是"组"不是"行"，塞进 A1 会破坏列表虚拟化 |
| A7 | 监测与索引设置（含进度/暂停/取消） | 3.1 / 3.2 | 首建是 3.8h 量级的事，进度必须常驻可见可中断 |
| A8 | 备份 / 恢复 / 迁移（向导式） | 3.8 | 覆盖用户数据，必须分步 + 校验 |

### 方案 B · 5 屏（合并低频界面，先做能跑的）

| # | 界面 | 合并了什么 |
| --- | --- | --- |
| B1 | 主窗口（库视图 + 搜索面板 同屏） | A1 + A2 |
| B2 | PDF 阅读器 | A3 |
| B3 | 归档预览/确认 + 操作日志/撤销 | A4 + A5 |
| B4 | 重复检测 | A6 |
| B5 | 设置（监测/索引/备份/恢复 用标签页） | A7 + A8 |

**取舍**：B 少 3 屏、开发快，代价是备份恢复被塞进设置标签页 —— 而它是最危险的操作之一，
放在标签页里容易被当成普通设置随手点。A 的问题是每个屏都要做，阶段 1–4 的界面工作量更大。
我建议 **A4/A5/A8 保持独立**（涉及磁盘与数据覆盖的动作不该藏进标签页），其余可按 B 合并；
但这是你的产品，按你勾的走。

## 三 · 无论选哪个方案，都已经由实测决定的界面约束

这些不是审美选择，是阶段 0 数字逼出来的，线框阶段就得遵守：

| 约束 | 来源 | 界面后果 |
| --- | --- | --- |
| 列表**必须虚拟化**，禁止一次渲染全部 | p0/p2：7,768 份、单目录最多 722 份、×10 档 8 万份 | 库视图与搜索结果都用 `QTableView` + 模型按需取行；不许 `QListWidget.addItem` 循环灌全量 |
| 打开文档**不能阻塞 UI** | p2：最大 946 页 / 1.1GB 单文件；`open_ms` 最差 232.7ms | 首屏先出文件名与元数据，正文页按需渲染（p3：单页 135.1ms 中位） |
| 搜索框需要**分档提示** | p1：<3 字 trigram 命中不了，需 LIKE 回退（2 字 499ms、单字 424ms） | 短查询要显示"正在用慢速匹配"并限制结果数，否则 500ms 门禁会被无感触发 |
| OCR / 语义是**可关闭的进度**，不是默认步骤 | p5：全量 1,144h；p6：全量 7.6h；G9 GPU 只能串行 | 必须有一条统一的"后台任务队列"状态区，并显示当前占用 GPU 的是哪个任务 |
| 索引体积要**当数据显示出来** | docs/03 2.9：索引 28–48GB | 设置里显示索引体积与磁盘剩余；按 2.9 选 2（子集索引）时更是核心指标 |
| 归档确认屏必须显示"跨盘" | SPEC 3.6 + docs/02 状态机（跨盘必须先复制校验再删源） | A4/B3 里每条计划行要能看出 同盘 rename / 跨盘 copy+verify+delete |
| 危险操作不得只靠一次点击 | SPEC 4.3 | A4/A8 用"输入确认词"或"复选框 + 显示影响条数"，不许 `QMessageBox.question` 一下就完 |
| 窗口最小宽度基线 | p3：离屏 1280×800 布局通过 | 线框按 1280×800 与 1440×900 两档画；最小宽度数值由你定，我不替你猜 |
