§1 S2 阅读器 · 「适应宽度」该长成什么形状（已勾 甲 = 要这一档；三案差在控件形状）

现有顶栏（reader_page.py:36-58）真实顺序是： [上一页] [页码] [下一页] —— addStretch() —— [放大] [缩小]。 三案都不动翻页那半边。

 底部那句（现有 status_label，objectName="muted"）一字不改。
  • 按下态：开着 = 按下；点「放大」或「缩小」任何一颗 ⇒ 立刻退出这一态（按钮弹起）， 倍率退回手动轴。不弹起就没法表达"我现在到底听谁的"。
  • 算式唯一：倍率 = 画布视口宽 ÷ 该页 1.0 倍时的渲染宽； 四档读数是 1.34／1.77／2.84／3.92（=799／1055／1695／2335 ÷ 596）。 这一态不受 3.0 的手动上限卡（卡了就永远占不满 2560 档 —— 那正是②的病）。
  • 像素预算（防极端小页算出天文倍率）：单次渲染像素总数上限 12,000,000px。 反算依据：A4 在 2560 档按适应宽度渲染 = 2333×3299 = 7.70M，留 1.5 倍余量； 超预算时按预算夹，此时横向留一点空是设计内的，断言放过这一种。
  • 窗口拉宽即重算：挂 Resize，形状与 _ViewportStretchPolicy 同一条 （只看 Resize、比 Python 包装对象、不回摸已销毁的 C++ 侧 —— 本轮实测那三条陷阱一条不少）。
  • 不跳页：换倍率与 resize 都不得动 _current_page 与页码那句。
