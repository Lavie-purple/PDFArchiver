**执行中**（同一个模态换状态，**不弹新窗**）：顶部读数变 `第 k/M 项｜当前项 journal 态：dst_verified`；
失败行就地变红并带 `error` 原文；结束时给「完成 x｜失败 y｜跳过 z｜**未动 M−k 项**」+「可撤销 n 项 → S4」。

**1024×720**：计数条换两行；过滤器收进「筛选」弹层；表格列按优先级砍 —— 先砍 `长度`，再缩 `源`，
`目标 / 方式 / 标记` **不许砍**（它们是 PROJECT_SPEC 3.6.5 明列的三项）。

## 区域 → 数据来源 → 可断言的硬条件

| 区域 | 数据从哪来（现成的，不新造） | 断言点 |
| --- | --- | --- |
| 计划表逐行 | `file_operations.plan_json`（一批次一个计划）+ `operation_items(src_path, dst_path, kind, state, reversible, error, src_sha256, dst_sha256)` | 表行数 **== `items_total`**；出现界面自己拼路径算出来的行判红（目标路径只能来自 plan） |
| 同盘 / 跨盘标记 | `documents.device_id` ↔ 目标根所在卷的 `st_dev` | **不许读 `volume_id`**（死列，**ISSUES I40**）；标记与 `operation_items.kind`（`move`/`copy`）必须一致，不一致判红 |
| 冲突列与展开 | plan 阶段的**只读**存在性检查 + 目标那份的 stat | 冲突项默认 `state='skipped'` 且带原因；"跳过"没有原因文本即判红 |
| 路径长度列 | `len(dst_path)`（目标串已在 plan 里） | **ISSUES I10** 欠的显示项：长度必须在行上可见，超阈值有标记 |
| 剩余空间 / 待复制总量 | `shutil.disk_usage(目标根)` + 库里 `SUM(size_bytes)` | 空间不足时 `[执行]` **禁用**并显示差额；把"禁用"改成"弹提示"判红 |
| 确认区计数 M/a/b/d | `items_total / items_done / items_failed` 与勾选项集合 | 四个数与勾选集合逐一对得上；出现自算的 `len(...)` 判红（与 S1 同一条规矩） |
| 执行中逐态 | journal JSONL 每态回写 | **界面态不得领先日志态**：断言"界面显示 done 时，journal 最后一行也是 done" |
| 完成态与撤销出口 | `file_operations.status`（`done｜partially_done｜failed`）+ `undo_of` | 界面不许造第四种状态说法；撤销只能跳 S4，本屏**不放撤销按钮**（两处入口做同一件事） |
| 模板回显 | `config/settings.py` 的 `archive_default_template` | 显示的串必须等于 `Settings.values[...]`；启动三件（默认值 / 覆盖值 / 来源文件）必须一并可查 |

## 两案的取舍

| | 甲 · 全量表常驻 | 乙 · 三段向导 |
| --- | --- | --- |
| 满足「逐条展示源/目标/重命名/冲突」（3.6.5） | **天然满足** | 要靠"展开完整计划"那条按钮才满足，**少写一条就变成只看例外就确认** |
| 8 万行档 | 虚拟化 + 默认过滤器；行高统一 | ②默认不列全量，压力小；但展开后**仍要虚拟化**，省不掉 |
| "我到底要动哪些文件"的确定感 | 一眼到底，代价是一屏信息密 | 分步、每步一件事，代价是要回看上一步的数 |
| 不可逆项的拦截强度 | 靠确认区单独计数 + 确认词 | 靠②逐条决定，人在环里的时间更长 |
| 实现与测试面 | 1 模态 + 1 张虚拟表 + 1 确认区 | 3 步 + 试算 + 分组处置 + 只读展开：**多一套步骤状态机要测**，而它测的是导航不是安全 |
| 与 S4 的分工 | 执行中 / 完成都留在本模态换状态 | 向导做完即关，中断与恢复读数只能全压给 S4 |

**我的推荐：甲 + 默认开启的过滤器。**
决定性理由：3.6.5 要的是**逐条展示**，乙 的默认形态（只看例外）与这条要求方向相反；
甲 用一个默认勾选的过滤器同时拿到"一屏看得完"和"全量随时可查"，
而且不必为向导新增一套步骤状态机 —— 阶段 4 的测试面应该花在 G17 / G18 / G19 那三条**磁盘安全**判据上，
不是花在"上一步 / 下一步"上。

## 两案的取舍

| | 甲 · 连续滚动 | 乙 · 单页翻页 |
| --- | --- | --- |
| 命中跳转后的位置感 | 好（还在同一文档流里，上下都有上下文） | 断（只有当前页） |
| 渲染压力 | **高**：135.1ms/页 vs 滚轮速度，必然跑输 → 必须定"滚动中不排队渲染，停下才渲染"这条策略 | **低**：一次一页，翻页即渲染，最坏值可预期 |
| 946 页 / 1.1GB 大文档 | 虚拟化上限 ≤5 页位图驻留，否则顶穿 `G8`（RSS ≤1.2GB） | 天然只有 1 页驻留 |
| 键盘党 | 方向键滚页 | `PgUp/PgDn` 直读，无歧义 |
| 双页并排（书册感） | 别扭 | 自然 |
| 实现与测试面 | 要测"滚动跑输渲染"的降级路径 | 少一条路径 |

**我的推荐：甲（连续滚动）+ 上限 5 页驻留 + "滚动中不排队、停下才渲染"。**
理由：这一屏的主角是**"从命中跳过来读那一段"**，连续流让命中处上下有上下文；
翻页式在"跳页—读—再跳页"的循环里每次都是白屏起步。渲染跑输滚轮这件事不是靠加阈值解决，
是靠**取消滚动中的渲染排队**这条策略解决，它是可断言的（测：连续滚轮事件期间渲染调用数 = 0）。

## 两案的取舍（说人话版）

| | 甲 · 三栏常驻 | 乙 · 一栏到底 |
| --- | --- | --- |
| 主动作 | "边看命中边归类"——树和命中都常驻 | "以文档为主、命中为注"——一屏一件事 |
| 虚拟化代价 | **低**：行高统一，`QTableView` 的行号↔坐标换算是 O(1) | **高**：行高随展开变化，要么关掉按需取行改为整表测高（在 8 万行档就是 O(n²)，AGENTS.md 明令禁止），要么限制"同时展开数"并为此加一条断言 |
| 1024 最小档 | 必须牺牲命中面板（改浮层）+ 树收图标条 | 天然适配 |
| 拖拽归类（选中→拖进分类） | **成立**，树常驻 | 不成立，得走"移入分类…"对话框 |
| 命中很多条时 | 面板自己滚，列表不动 | 列表里插满命中行，位置感变差 |
| 开发顺序 | S1 一次到位 | S1 简单，但"同时展开数"这类限制要另写规则 |

**我的推荐：甲 + 1024 下降级成"命中面板浮层 + 树收图标条"。**
决定性理由是虚拟化那一行：乙的变行高会把 O(1) 的行号换算打回 O(n)，
而这正是 AGENTS.md「禁止全量渲染 / 禁止 O(n²)」在项目里唯一会**被 UI 自己犯掉**的地方
（阶段 0–5 的禁令都在后端和文档里，没碰过列表控件）。
